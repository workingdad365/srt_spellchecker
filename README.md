# srt-spellchecker

SRT 자막 파일의 오타와 맞춤법을 LLM으로 교정하는 PySide6 데스크톱 애플리케이션.
HARDSUB 추출 후 OCR로 생성한 파일이나, 개인 제작 자막의 교정 용도로 사용.

## 특징

- 라디오버튼으로 LLM 교정 모드와 Kiwi 기반 간이평가 모드 전환
- 간이평가 완료 후 파일별 띄어쓰기 오류 수를 내림차순으로 표시
- 파일 다중 선택 및 파일·폴더 드래그 앤드 드롭
- 폴더와 모든 하위 폴더의 SRT 일괄 교정, 중복 경로 제거
- UI에서 서비스별 API 키 입력, 모델 목록 조회 및 검색 가능한 콤보박스 선택
- 마지막 서비스·서비스별 모델·교정 옵션 자동 저장 및 복원, API 키의 OS 자격 증명 저장소 보관
- OpenRouter 모델 메타데이터에 따른 추론 비활성화 또는 지원하는 최저 강도 선택
- 백그라운드 파일 탐색·모델 조회·교정, 진행률·파일별 상태·중단 지원
- 대사 구분 표기를 각 발언 앞의 `- `로 통일하고 서식 줄의 경계 유지
- 말줄임표를 ASCII 점 세 개(`...`)로 통일
- 문장 끝 마침표 생략, 줄 끝 단일 마침표 자동 제거
- 문맥에 맞는 비속어·욕설 순화 및 사투리의 표준어 변환
- 단독 한자어의 한국식 독음 변환, 괄호 안 한자 부연 표기 유지
- 자막 번호, 타임코드, 비자막 블록, 줄바꿈(CRLF/LF), BOM 유무를 원본 그대로 유지
- UTF-8(BOM 포함) 입력 지원, CP949 입력은 UTF-8로 변환해 저장
- LLM 교정 결과를 수용하며 태그·대사·줄 구성 변경을 원본으로 되돌리지 않음
- 빈 응답·빈 줄이 포함된 응답만 예외로 해당 자막 블록의 원문 유지 및 수동 검토 안내
- 최종 3줄 이상·설정 길이 초과는 결과를 유지한 채 수동 검토 안내
- LLM에는 줄바꿈·대사 구분 규칙을 지시하되 응답을 코드에서 자동 재구성하거나 재분할하지 않음
- 배치 단위 재시도 (최대 3회), 끝내 실패한 배치는 원본을 유지하고 나머지를 계속 처리
- 수동 검토/누락/실패 내역을 GUI 검토 로그로 표시
- **긴 줄 나누기** 설정으로 LLM에 최대 2줄 분할 요청 (기본 23자), 미준수 시 검토 안내만 표시

## 간이평가 모드

화면 상단에서 **간이평가**를 선택하고 파일·폴더 추가 또는 드래그 앤드 드롭으로 SRT를 가져온 뒤 **평가 시작**을 누른다. API 키 없이 로컬 Kiwi 형태소 분석기로 띄어쓰기를 평가하고 이후 자막 시작시간 순서를 검사한다. 최초 평가에는 Kiwi 모델 초기화 시간이 필요하다.

**UTF-8이 아닌 자막은 평가 전에 원본을 UTF-8 BOM 형식으로 교체한다.** UTF-8은 BOM 유무와 관계없이 그대로 유지한다. UTF-16·UTF-32의 양쪽 바이트 순서와 CP949/KS X 1001(EUC-KR) 계열을 지원하며, BOM 없는 UTF-16·UTF-32는 SRT 구조를 확인해 판별한다. 변환 시 본문·번호·타임코드·줄바꿈은 유지하고 `_revised` 파일은 만들지 않는다. 임시 파일 저장이 완료되면 원본을 교체하고, 교체된 파일을 다시 읽어 Kiwi 평가를 진행한다. 해독 불가·유효한 SRT 블록 없음·교체 실패 시 원본을 덮어쓰지 않고 해당 파일은 실패로 처리한다. 변환 완료는 로그와 평가 상태 툴팁에 표시하며, 이후 평가가 실패하거나 중단되어도 완료된 인코딩 변환은 되돌리지 않는다.

오류 수는 원문과 Kiwi의 띄어쓰기 결과를 비교하여 공백을 삽입·삭제해야 하는 문자 사이 위치당 1건으로 집계한다. 한 줄에 여러 오류가 있으면 각각 합산한다. 줄별로 분석하므로 자막 줄바꿈 자체는 집계하지 않으며 번호·타임코드·서식 태그·줄 시작 대사 표식도 제외한다. 연속 공백의 개수와 줄 양끝 공백은 집계하지 않는다. 형태소 분석에 따른 추정치이므로 문맥이나 고유명사에 따라 실제 오류와 차이가 있을 수 있다.

평가 결과 표에 파일별 상태, 오류 수, 글자 수와 **1,000자당 오류 수**를 표시한다. 빈도는 `오류 수 ÷ 글자 수 × 1,000`으로 계산하고 소수점 둘째 자리까지 표시한다. 글자 수는 평가 대상 본문에서 공백·줄바꿈·서식 태그·줄 시작 대사 표식을 제외한 문자 수이며 문장부호는 포함한다. 예를 들어 10,000자에서 오류 20건이면 1,000자당 2.00건이다. 본문 글자 수가 0이면 빈도는 `—`로 표시한다.

본문에 섞인 보이지 않는 BOM 문자(`U+FEFF`)는 분석과 글자 수 집계에서 제외하며 원본 파일은 유지한다.

Kiwi가 공백 외 문자를 추가·삭제·변경한 줄은 오류 수와 글자 수 집계에서 함께 제외하고 나머지 줄의 평가를 계속한다. 해당 파일은 **부분 평가 (N줄 제외)**로 표시하며 오류율도 정상적으로 분석된 줄만을 기준으로 계산한다. 평가 상태 셀의 툴팁과 `[제외]` 로그에 자막 번호·본문 줄 번호·분석 입력·Kiwi 결과를 기록한다. 모든 분석 대상 줄이 제외되면 **평가 불가**로 표시하고 수치는 `—`로 남기며, 종료 요약의 실패 수에 포함한다. 파일 읽기나 분석기 실행 자체의 오류는 기존처럼 파일 평가 실패로 처리한다. 인코딩 변환 외에 본문을 자동 교정하지 않는다.

Kiwi 평가 후 파일에 기록된 자막 순서대로 시작시간을 밀리초 단위로 비교한다. 현재 시작시간이 직전 자막보다 이르면 **검토 필요**로 표시하고, 역행한 자막 번호와 직전·현재 시작시간을 로그·툴팁·**검토** 아이콘의 대화상자에서 확인할 수 있다. 동일한 시작시간과 종료시간 중첩은 역행으로 보지 않는다. 시작시간 형식을 읽을 수 없는 블록도 수동 검토 대상으로 기록한다. 번호·시간을 자동 정렬하거나 수정하지 않으며, 시간 문제는 띄어쓰기 오류 수에 합산하지 않는다. 부분 평가·평가 불가와 검토 필요 상태는 함께 표시할 수 있고 기존 LLM 교정 상태·검토 내역에는 영향을 주지 않는다.

자막 본문에 `KRCC`, `EGCC`, `&nbsp` 문자열이 포함된 경우에도 **검토 필요**로 표시한다. 대소문자를 구분하지 않으며 `&nbsp;`처럼 세미콜론이 붙은 경우도 포함한다. 해당 자막 번호·본문 줄 번호·발견 문자열·원문을 검토 내역과 CSV에 기록한다. Kiwi에서 제외된 줄도 검사하며 문자열을 자동 삭제하거나 띄어쓰기 오류 수에 합산하지 않는다.

전체 작업이 끝나면 오류 수가 많은 순으로 한 번 정렬하며 이후 열 제목을 눌러 빈도순 등으로 정렬할 수 있다. 정렬에는 반올림 전 숫자를 사용한다. 실패·미처리 파일은 수치를 `—`로 표시하여 정상적인 0건과 구분하고 기본 내림차순 정렬에서 아래에 배치한다. 중단 시에도 완료한 결과를 유지하며 다시 시작하면 현재 목록 전체를 재평가한다. 평가 결과는 현재 실행에서만 유지하며 기존 LLM 교정 상태와 결과는 모드 전환 후에도 유지한다.

평가 종료 후 **1,000자당 오류 수** 기준값을 입력하고 **기준 이상만 남기기**를 누르면 해당 값 이상인 파일만 평가 결과와 공용 파일 목록에 남긴다. 비교에는 반올림 전 오류율을 사용하며 기준값과 같은 항목도 포함한다. 기준 미만, 평가 실패·미평가 및 글자 수 0으로 오류율이 없는 항목은 목록에서 제거한다. 원본·결과 파일은 삭제하지 않으며 정리된 파일 목록은 저장한다. 이후 **LLM 교정**으로 전환하고 모델을 선택해 **교정 시작**을 누르면 남은 파일을 대상으로 교정한다. 이미 교정 완료된 파일의 재처리 제외 규칙은 유지한다. 평가·교정·파일 불러오기가 진행 중이면 목록 필터를 사용할 수 없다.

부분 평가 결과도 계산된 오류율로 필터링할 수 있지만 전체 파일을 평가한 값은 아니므로 제외 내역을 함께 확인해야 한다. 검토 필요 파일도 오류율 기준으로 필터링하므로 기준 미만이면 목록에서 제거된다. CSV에는 부분 평가·평가 불가·검토 필요 상태와 제외 줄 수를 표시하고, **검토** 열에 자막 번호·시작시간을 포함한 검토 내역을 저장한다.

평가 결과 테이블의 **평가 자막** 셀을 더블클릭하면 해당 파일을 시스템 기본 연결 프로그램으로 연다. **평가 상태** 셀을 더블클릭하면 해당 파일이 있는 폴더를 탐색기로 연다. 정렬 후에도 선택한 행의 파일과 폴더를 연다.

평가 완료 또는 중단 후 **CSV 내보내기**를 누르면 평가 테이블의 열 제목, 현재 정렬 순서와 표시 값을 그대로 저장한다. 실패·미처리 행과 `—` 표시도 포함한다. CSV는 Excel에서 한글을 읽을 수 있도록 UTF-8 BOM 형식으로 저장하며, 평가 중이거나 결과가 없으면 내보내기를 비활성화한다.

평가 테이블의 **평가 자막**은 `상위 폴더명\파일명`으로 표시하며 CSV에도 같은 표시를 저장한다. 전체 경로는 해당 셀에 마우스를 올려 확인할 수 있다.

LLM 교정 목록의 **원본 자막**과 **결과 파일**도 같은 `상위 폴더명\파일명` 형식으로 표시한다. 전체 경로는 셀의 툴팁에 유지한다.

## 비속어 순화 및 표준어 변환

교정 시 LLM에 강한 비속어·욕설만 문맥에 맞게 완화하도록 지시한다. '젠장', '제길', '놈', '자식' 정도의 가벼운 비속어는 원문에 있으면 유지하고 강한 욕설의 순화 결과로도 허용한다. 분노와 거친 말투를 과도하게 약화하지 않으며 원문보다 공격성을 높이거나 불필요한 비속어를 덧붙이지 않는다. 사투리의 어휘·어미는 자연스러운 표준어로 변환한다. 원래 뜻과 감정, 존댓말·반말 구분은 유지하며 대사 삭제나 내용 추가는 하지 않는다. 정상적인 단어나 고유명사를 부분 일치만으로 치환하지 않는다.

변환은 고정 치환 사전이 아닌 모델의 문맥 판단에 따르므로 결과는 모델에 따라 달라질 수 있다. 뜻이나 대응 표현이 불확실하면 원문을 유지하도록 모델에 지시한다. 코드에서는 반환된 교정 결과를 수용하되, 빈 응답·빈 줄이 포함된 응답이나 응답 누락·API 실패에는 원문 유지 규칙을 적용한다.

## 한자 독음 변환

본문에 한자로만 적힌 단어는 한국식 한자 독음의 한글로 바꾸도록 LLM에 지시한다. `主君`은 `주군`, `主君을 모셔라`는 `주군을 모셔라`로 변환하며 뜻풀이나 중국어·일본어 발음으로 바꾸지 않는다.

`주군(主君)`이나 `주군（主君）`처럼 한글 표현을 부연하는 괄호 안 한자는 괄호와 함께 유지한다. 같은 줄에 두 형태가 섞여 있으면 `주군(主君)과 主君`은 `주군(主君)과 주군`으로 변환한다. 고유명사도 한국식 독음을 적용하되, 독음을 확신할 수 없으면 원문을 유지하도록 지시한다. 실제 변환과 예외 준수는 모델의 문맥 판단에 따른다.

## 말줄임표 교정

자막 본문의 `..`, `....`, `......`처럼 연속된 점과 `…`, `……`, `⋯`, `‥`, 세로 말줄임표(`︙`, `︰`), 연속된 전각 점(`．．`)을 모두 `...`로 통일한다.

- `잠깐.. 기다려…` → `잠깐... 기다려...`
- 소수점과 문장 중간의 단일 점은 이 정규화에서 유지하며, 줄 끝 단일 마침표는 아래 규칙으로 제거함
- 모델이 추가한 말줄임표도 같은 표기로 정규화하며 추가 여부만으로 되돌리지 않음
- 모델 응답 누락·실패로 원문을 유지하는 경우에도 말줄임표 표기 통일은 적용함
- 자막 번호·타임코드·비자막 블록은 이 규칙으로 변경하지 않음

## 문장 끝 마침표 교정

한국어 자막 관례에 따라 문장 끝 마침표를 생략하도록 모델에 지시한다. 줄 끝의 단일 마침표는 모델 호출 전과 응답 검증 전에 코드에서도 제거한다. 닫는 따옴표·괄호·서식 태그와 공백 앞의 줄 끝 마침표도 제거한다.

- `안녕하세요.` → `안녕하세요`
- `"안녕하세요."` → `"안녕하세요"`
- `<i>안녕하세요.</i>` → `<i>안녕하세요</i>`
- `잠깐..`, `잠깐…` → `잠깐...` (말줄임표를 먼저 통일한 뒤 그대로 유지함)
- `값은 3.14.` → `값은 3.14` (소수점 유지)

모델 응답 누락·실패로 원문을 유지하는 경우에도 줄 끝 마침표 제거를 적용한다. 같은 줄 안의 문장 경계 판단은 모델에 맡기며, 코드는 내부 단일 점을 일괄 삭제하지 않는다. 자막 번호·타임코드·비자막 블록은 변경하지 않는다.

## 대사 구분 교정

일반 문장은 원래 줄바꿈을 유지하도록 LLM에 지시한다. 짧거나 한 줄에 들어간다는 이유, 같은 문장이나 같은 사람의 발언이라는 이유만으로 두 줄을 합치지 않도록 요청한다. 줄 구성 변경은 대사 표식 정리와 활성화된 긴 줄 나누기에 필요한 경우로 제한하도록 요청하지만, 반환된 결과를 코드에서 되돌리지는 않는다.

한 자막 블록에서 줄 시작의 `/` 또는 `-`로 구분된 발언은 별도 줄로 유지한다. 대사 표식으로 여러 발언이 구분된 블록을 정리할 때에는 같은 발언의 여러 줄을 공백으로 연결하여 한 줄로 만들고, 각 발언 앞에 하이픈과 공백 한 칸(`- `)을 붙인다. 세 발언 이상도 두 줄로 강제 병합하지 않는다. LLM 입력에도 발언 단위로 정리한 줄을 전달한다.

입력:

```text
노부시(일종의 산적)가 다 털고 간 뒤에
나타나선 떵떵거릴걸?
/ 맞아, 맞아
```

결과:

```text
- 노부시(일종의 산적)가 다 털고 간 뒤에 나타나선 떵떵거릴걸?
- 맞아, 맞아
```

`마시지요 /네`처럼 한국어 문장 종결 뒤에 공백과 `/`가 있고 한국어 대사가 이어지면 줄을 나눈다. 경로·URL·분수·`커피/차`나 `커피 / 차` 같은 표기는 분리하지 않는다. 이 판별은 표기 규칙에 따른 추정이며 실제 화자를 알아내는 기능은 아니다.

서식 태그가 있는 줄은 설명 자막일 수 있으므로 LLM 입력에서는 인접 대사와 별도 구간으로 보존한다. 응답의 태그 수정·삭제, 대사 표식 이동·변경, 줄 병합·분리는 모두 수용한다. 예를 들어 `<ㅑ>`를 `<i>`로 수정한 결과를 원본 태그와 다르다는 이유로 되돌리지 않는다. 응답에 원본 대사 표식을 강제로 복구하지 않는다.

긴 줄 나누기를 켜도 코드에서는 모델 결과를 재분할하거나 병합하지 않는다. 설정 길이를 넘으면 결과를 유지하고 `[확인필요]` 로그를 남긴다. 최종 자막이 3줄 이상이면 긴 줄 나누기 설정과 관계없이 `[확인필요]`로 표시한다. 줄 수 검사는 응답 누락·실패로 유지된 원본에도 적용하며, 타임스탬프 변경이나 다른 블록으로의 대사 이동은 수행하지 않는다. 코드에서 의미·대사·서식 경계의 정확성을 판정하지 않는다.

## 데스크톱 실행

Python 3.12 이상과 `uv`가 필요하다. 프로젝트 디렉터리에서 실행한다.

```powershell
uv run srt-spellchecker
```

전역 명령으로 설치하거나 기존 설치를 갱신한다.

```powershell
uv tool install --editable --force .
srt-spellchecker
```

`srt-spellchecker`로 GUI를 실행하며 Windows에서 별도 콘솔 창을 만들지 않는다. 파일 인자와 명령행 교정 옵션은 제공하지 않는다. 파일 추가와 모든 설정은 GUI에서 수행한다.

1. **AI 서비스**에서 OpenAI 또는 OpenRouter를 선택한다.
2. **API 키**를 입력하고 **모델 가져오기**를 누른다.
3. 조회된 모델을 콤보박스에서 선택한다. 모델 ID 일부를 입력해 검색할 수 있다.
4. **파일 추가**, **폴더 추가** 또는 파일 목록으로 드래그 앤드 드롭하여 대상을 추가한다.
5. 필요하면 **긴 줄 나누기**와 최대 글자 수를 설정하고 **교정 시작**을 누른다.

**동시 교정 파일 수**를 1~32개로 지정할 수 있다. 기본값 1개는 순차 처리이며, 2개·3개 등으로 바꾸면 해당 개수만큼 파일을 동시에 교정한다. 한 파일이 끝나면 대기열의 다음 파일을 바로 시작한다. 설정은 자동 저장되며 실행 중에는 변경할 수 없다. 파일 내부의 배치는 순차 처리한다.

**요청당 자막 수**는 API 요청 한 번에 보낼 자막 블록 수이며 1~200개로 지정할 수 있다. 기본값은 25개다. 자막 번호와 타임스탬프 하나에 속한 대사 전체를 1개로 센다. 마지막 배치는 남은 자막만 보낸다. 설정은 자동 저장·복원되고 다음 교정부터 적용되며, 작업 중에는 변경할 수 없다. 동시 교정하는 모든 파일에 같은 값을 적용하고 교정 시작 로그에 표시한다.

전체 진행률은 파일별 진척도의 평균으로 표시하고 로그에는 대상 파일 경로를 붙인다. 중단하거나 창을 닫으면 모든 실행 중 파일에 중단을 요청하고 진행 중 API 응답을 기다린다. 완료한 파일은 유지하며 미완료 파일은 저장하지 않는다. 인증 등 치명적인 API 오류가 발생하면 새 파일을 시작하지 않고 나머지 실행 중 작업에도 중단을 요청한다.

요청 제한(429) 시 서버의 `Retry-After` 또는 `retry-after-ms`에 따라 대기하고, 없으면 지수 대기와 무작위 지연을 적용한다. 기존과 같이 배치당 최대 3회 시도하며 대기 중에도 중단할 수 있다. 동시 파일 수의 상한 32는 앱 설정 범위이며 실제 처리 가능 수는 서비스·모델·계정 제한에 따라 달라진다.

서비스, 서비스별 마지막 모델, 긴 줄 나누기 여부와 최대 글자 수는 변경 시 자동 저장하고 다음 실행 때 복원한다. 모델의 추론·출력 형식 메타데이터도 함께 저장하므로 마지막 모델은 목록을 다시 조회하지 않아도 사용할 수 있다. 다른 모델을 선택하거나 최신 지원 정보를 반영하려면 **모델 가져오기**를 누른다. 갱신된 목록에 마지막 모델이 있으면 자동 선택하고, 없으면 저장된 선택을 해제한다.

API 키는 기본적으로 가려지며, UI 입력을 잠시 멈추거나 입력란을 벗어날 때, 서비스 전환·모델 조회·교정 시작·종료 시 자동 저장한다. Windows에서는 자격 증명 관리자에 서비스별로 분리하여 저장하고, 일반 설정에는 키를 넣지 않는다. macOS에서는 Keychain, Linux에서는 Secret Service를 사용한다. 저장소 이용에 실패하면 오류를 표시하고 현재 실행에서만 키를 사용하며, 평문 파일로 대체하지 않는다.

API 키와 모델·교정 옵션은 GUI에서 입력·선택한 값 및 저장된 값만 사용한다. `.env` 파일이나 API 키·모델 관련 환경변수는 읽지 않는다. 저장된 키가 없으면 빈 입력란으로 시작한다. 키 입력란을 비우고 다른 컨트롤을 선택하면 해당 서비스의 저장된 키가 삭제되며 다음 실행에도 빈 입력란을 유지한다. 키를 변경한 직후에는 모델 목록을 다시 조회해야 한다. 자막 내용은 선택한 서비스로 전송되며 사용 요금은 해당 서비스의 정책을 따른다.

일반 설정은 Qt 설정 저장소를 사용하며 Windows 위치는 `HKEY_CURRENT_USER\Software\drasys\srt-spellchecker`다. 전체 실행 로그는 복원하지 않으며, 키 표시 상태는 매번 가림으로 시작한다.

작업 목록은 파일 추가·제거·상태 변경 때마다 별도 JSON 파일에 원자적으로 저장한다. Windows 기본 위치는 `%LOCALAPPDATA%\srt-spellchecker\worklist.json`이며 API 키는 저장하지 않는다. 정상 종료와 비정상 종료 후 모두 마지막 저장된 목록 순서, 파일별 상태, 결과 경로와 검토 내역을 복원한다. 종료 시 **교정 중**이던 파일은 **대기**로 복원하며, 자동 실행하지 않고 **교정 시작**으로 미완료 파일을 다시 처리한다. 파일 내부 배치 단위의 이어하기는 지원하지 않는다.

**목록 비우기**를 누르면 저장된 목록도 비워 다음 실행에 다시 나타나지 않는다. 개별 파일 제거 역시 저장에 반영한다. 저장 실패 시 오류를 표시하며, 저장 도중 종료되면 마지막으로 저장이 완료된 목록을 사용한다.

폴더 추가 시 `.srt` 확장자는 대소문자를 구분하지 않으며, 기존 `_revised.srt`도 포함한 모든 SRT를 탐색한다. 심볼릭 링크 폴더는 순환 방지를 위해 재귀 탐색하지 않는다. 목록에서 제외할 파일을 선택해 제거할 수 있다. 실행 중 생성된 결과는 현재 작업 목록에 자동 추가하지 않는다.

파일·폴더를 불러오는 동안 목록 위에 움직이는 로딩 바와 현재 탐색에서 발견한 SRT 개수를 표시한다. 표시 문구에 마우스를 올리면 탐색 경로를 확인할 수 있다. 전체 파일 수를 미리 알 수 없어 완료 백분율은 표시하지 않으며, 교정 진행률과 별도로 동작한다. 탐색이 완료·실패·중단되면 로딩 표시를 숨긴다.

교정 중에도 파일·폴더를 드래그 앤드 드롭하거나 추가 버튼으로 대기열에 넣을 수 있다. 새 파일은 기존 작업 뒤에서 추가 순서대로 자동 교정한다. 각 행의 **제거** 아이콘으로 **대기** 상태 파일만 대기열에서 제외할 수 있으며 원본 파일은 삭제하지 않는다. 이미 교정 중이거나 처리가 끝난 파일의 제거 버튼은 비활성화한다. 작업 중 전체 목록 삭제와 교정 설정 변경은 잠근다.

**완료** 및 **검토 필요** 파일은 다시 교정하지 않으며, 목록에서 복원된 완료 파일도 재처리 대상에서 제외한다. 같은 앱 실행 중에는 목록을 비우고 같은 경로를 추가해도 제외한다. 모든 대상의 처리가 완료되면 **교정 시작**은 새 파일을 추가할 때까지 비활성화한다. 실패·중단·미처리 파일은 **교정 시작**으로 재시도할 수 있다.

결과는 원본 옆의 `<원본파일명>_revised.srt`에 저장한다. GUI는 원본과 기존 결과를 덮어쓰지 않으며 이름이 겹치면 `_revised_2.srt`, `_revised_3.srt`처럼 번호를 붙인다. 파일 목록에서 원본 자막이나 결과 파일을 더블클릭하면 시스템에 연결된 기본 프로그램으로 해당 파일을 연다. `.srt` 파일이 노트패드++에 연결되어 있으면 노트패드++로 연다. 상태 셀(완료·검토 필요 등)을 더블클릭하면 원본 자막이 있는 폴더를 탐색기로 연다.

**중단**은 진행 중인 API 요청이 끝난 뒤, 다음 재시도·배치·파일에 들어가기 전에 적용된다. 요청 제한 시간은 교정 180초, 모델 조회 30초다. 완료된 파일은 남기며 중단된 파일은 저장하지 않는다. 작업 중 창을 닫으면 중단 확인 후 작업 종료까지 기다린다.

개별 파일 읽기·저장 오류는 로그를 남기고 다음 파일로 진행한다. 인증·권한·잘못된 요청·없는 모델 오류는 작업 큐를 중단한다. 배치 교정 실패 등으로 일부 원문을 유지한 결과는 **검토 필요**로 표시한다.

**검토 필요** 파일의 **검토** 아이콘을 누르면 해당 파일의 원본·결과 경로와 검토 내역만 별도 창으로 표시한다. 다른 파일의 교정 중에도 열 수 있으며, 전체 로그가 지워지거나 표시 한도를 넘어도 목록에 남아 있는 파일의 검토 내역은 유지한다. 재실행 시에도 복원하며, 파일을 목록에서 제거하거나 목록을 비우면 저장된 검토 내역도 해제한다.

## 검토 로그

LLM이 반환한 교정 결과는 빈 응답·빈 줄 예외를 제외하고 원본으로 되돌리지 않는다. 문장부호·태그·대사 표식·줄 구성 변경 자체로 검토 경고를 남기지 않으며, 기존 말줄임표 표준화와 줄 끝 마침표 생략만 계속 적용한다. 새 `[되돌림]`·`[재분할]` 로그는 생성하지 않고 이전 버전의 기록은 그대로 유지한다.

최종 3줄 이상과 긴 줄 나누기 설정 길이 초과는 결과를 유지하면서 수동 검토를 안내한다. 빈 배열·공백뿐인 응답·빈 줄이 포함된 응답은 그대로 저장하지 않고 해당 자막 블록 전체를 원문으로 유지한다. 문자열 내부나 끝의 줄바꿈으로 생긴 빈 줄도 같은 예외를 적용한다. 이 경우 `[확인필요]`에 원문 유지 사유와 원본·모델 응답의 줄 수 및 JSON 배열을 함께 기록한다. 유지된 원문에도 기존 문장부호 정리와 최종 줄 수·길이 검사를 적용한다. 검토 내역은 파일별 검토 창과 저장된 작업 목록에 유지한다.

응답 누락·API 실패·응답 해석 실패로 유효한 교정 결과를 받지 못한 경우는 결과 수용과 별개로 원문을 유지하고 `[누락]`·`[실패]`를 기록한다. 자막 번호·타임코드와 비자막 블록은 기존대로 유지한다.

| 태그 | 의미 |
|---|---|
| `[확인필요]` | 3줄 이상·설정 길이 초과는 결과 유지, 빈 응답·빈 줄은 원문 유지 후 수동 검토 |
| `[누락]` | 모델 응답에 해당 자막이 없어 원본 유지 |
| `[실패]` | 배치가 재시도 후에도 실패해 원본 유지 |

## 모델 관련 참고

- OpenAI와 OpenRouter의 모델 목록 API를 호출하며 모델 ID와 OpenRouter 메타데이터를 보존함
- OpenRouter는 `reasoning.mandatory: false`이면 `reasoning.enabled: false`로 추론을 비활성화함
- 필수 추론 모델은 `supported_efforts` 중 `minimal`, `low`, `medium`, `high`, `xhigh`, `max` 순서로 지원하는 최저 강도를 선택함
- `supported_efforts: null`은 모든 강도 허용으로 해석하되 필수 추론 모델에 `none`을 보내지 않음
- 메타데이터 또는 강도 선택 정보가 없으면 지원 값을 추측하지 않고 모델 기본값을 사용함
- `exclude: true`는 추론 내용의 응답 제외이며, 자체적으로 추론 비용을 줄이는 옵션은 아님
- OpenAI 모델 목록에는 추론 지원 강도가 없으므로 GUI에서는 추론 파라미터를 강제하지 않음
- Chat Completions API를 사용함. OpenRouter는 `structured_outputs` 지원 시 JSON 스키마, `response_format`만 지원하면 JSON 모드, 둘 다 없으면 프롬프트로 JSON을 요청함. 응답은 항상 Pydantic으로 검증함
- OpenAI는 JSON 스키마 구조화 출력을 사용함. 목록에 표시되더라도 선택한 모델이 텍스트 교정·Chat Completions·구조화 출력을 지원하지 않으면 API 오류가 표시될 수 있음

OpenRouter 추론 정책 기준: [Reasoning Tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).
