# srt-spellchecker

SRT 자막 파일의 오타와 맞춤법을 LLM으로 교정하는 PySide6 데스크톱 애플리케이션.
HARDSUB 추출 후 OCR로 생성한 파일이나, 개인 제작 자막의 교정 용도로 사용.

## 특징

- 파일 다중 선택 및 파일·폴더 드래그 앤드 드롭
- 폴더와 모든 하위 폴더의 SRT 일괄 교정, 중복 경로 제거
- UI에서 서비스별 API 키 입력, 모델 목록 조회 및 검색 가능한 콤보박스 선택
- 마지막 서비스·서비스별 모델·교정 옵션 자동 저장 및 복원, API 키의 OS 자격 증명 저장소 보관
- OpenRouter 모델 메타데이터에 따른 추론 비활성화 또는 지원하는 최저 강도 선택
- 백그라운드 파일 탐색·모델 조회·교정, 진행률·파일별 상태·중단 지원
- 두 사람의 대사 구분 표기를 각 줄 앞의 `- `로 통일 (GUI·CLI 공통)
- 말줄임표를 ASCII 점 세 개(`...`)로 통일 (GUI·CLI 공통)
- 문장 끝 마침표 생략, 줄 끝 단일 마침표 자동 제거 (GUI·CLI 공통)
- 자막 번호, 타임코드, 비자막 블록, 줄바꿈(CRLF/LF), BOM 유무를 원본 그대로 유지
- UTF-8(BOM 포함) 입력 지원, CP949 입력은 UTF-8로 변환해 저장
- 모델이 규칙을 어긴 줄은 코드에서 원본으로 되돌림
  - 줄 수가 달라진 자막
  - 원본에 없던 문장부호가 추가된 줄 (대사 구분용 하이픈과 기존 말줄임표 표기 통일은 예외, 줄 끝 단일 마침표는 검증 전에 제거)
- 배치 단위 재시도 (최대 3회), 끝내 실패한 배치는 원본을 유지하고 나머지를 계속 처리
- 되돌림/누락/실패 내역을 검토 로그로 출력 (stderr)
- `--wrap` 옵션으로 긴 줄을 최대 2줄로 나눔 (기본 23자)

## 말줄임표 교정

자막 본문의 `..`, `....`, `......`처럼 연속된 점과 `…`, `……`, `⋯`, `‥`, 세로 말줄임표(`︙`, `︰`), 연속된 전각 점(`．．`)을 모두 `...`로 통일한다.

- `잠깐.. 기다려…` → `잠깐... 기다려...`
- 소수점과 문장 중간의 단일 점은 이 정규화에서 유지하며, 줄 끝 단일 마침표는 아래 규칙으로 제거함
- 원문에 없던 말줄임표를 모델이 추가하는 것은 기존 문장부호 검증으로 차단함
- 모델 응답 누락·실패로 원문을 유지하는 경우에도 말줄임표 표기 통일은 적용함
- 자막 번호·타임코드·비자막 블록은 이 규칙으로 변경하지 않음

## 문장 끝 마침표 교정

한국어 자막 관례에 따라 문장 끝 마침표를 생략하도록 모델에 지시한다. 줄 끝의 단일 마침표는 모델 호출 전과 응답 검증 전에 코드에서도 제거한다. 닫는 따옴표·괄호·서식 태그와 공백 앞의 줄 끝 마침표도 제거한다.

- `안녕하세요.` → `안녕하세요`
- `"안녕하세요."` → `"안녕하세요"`
- `<i>안녕하세요.</i>` → `<i>안녕하세요</i>`
- `잠깐..`, `잠깐…` → `잠깐...` (말줄임표를 먼저 통일한 뒤 그대로 유지함)
- `값은 3.14.` → `값은 3.14` (소수점 유지)

모델 응답 누락·실패나 검증에 따른 되돌림에도 줄 끝 마침표 제거를 적용한다. 같은 줄 안의 문장 경계 판단은 모델에 맡기며, 코드는 내부 단일 점을 일괄 삭제하지 않는다. 자막 번호·타임코드·비자막 블록은 변경하지 않는다.

## 대사 구분 교정

한 자막 블록이 비어 있지 않은 두 줄이며 둘째 줄이 `/` 또는 `-`로 시작하면 두 사람의 대사로 처리한다. 각 줄 앞의 표식을 하이픈과 공백 한 칸(`- `)으로 통일하며, 첫째 줄에 표식이 없으면 추가한다.

입력:

```text
아메리카노 한 잔 주세요
/예 손님, 잠시만 기다려 주세요
```

결과:

```text
- 아메리카노 한 잔 주세요
- 예 손님, 잠시만 기다려 주세요
```

표식이 없는 일반 두 줄 자막이나 문장 중간의 `/`는 이 규칙으로 변경하지 않는다. 대사 표기 외의 문장부호 추가 방지 규칙은 유지한다. 긴 줄 나누기를 켜도 두 사람의 대사는 서로 합치거나 재분할하지 않으며, `- `를 포함한 길이가 제한을 넘으면 `[확인필요]` 로그를 남긴다.

## 데스크톱 실행

Python 3.12 이상과 `uv`가 필요하다. 프로젝트 디렉터리에서 실행한다.

```powershell
uv run srt-spellchecker
```

전역 명령으로 설치하거나 기존 설치를 갱신한다.

```powershell
uv tool install --editable --force .
srt-spellchecker
```

Windows에서 콘솔 창 없는 실행 진입점은 `srt-spellchecker-gui`다.

1. **AI 서비스**에서 OpenAI 또는 OpenRouter를 선택한다.
2. **API 키**를 입력하고 **모델 가져오기**를 누른다.
3. 조회된 모델을 콤보박스에서 선택한다. 모델 ID 일부를 입력해 검색할 수 있다.
4. **파일 추가**, **폴더 추가** 또는 파일 목록으로 드래그 앤드 드롭하여 대상을 추가한다.
5. 필요하면 **긴 줄 나누기**와 최대 글자 수를 설정하고 **교정 시작**을 누른다.

서비스, 서비스별 마지막 모델, 긴 줄 나누기 여부와 최대 글자 수는 변경 시 자동 저장하고 다음 실행 때 복원한다. 모델의 추론·출력 형식 메타데이터도 함께 저장하므로 마지막 모델은 목록을 다시 조회하지 않아도 사용할 수 있다. 다른 모델을 선택하거나 최신 지원 정보를 반영하려면 **모델 가져오기**를 누른다. 갱신된 목록에 마지막 모델이 있으면 자동 선택하고, 없으면 저장된 선택을 해제한다.

API 키는 기본적으로 가려지며, UI 입력을 잠시 멈추거나 입력란을 벗어날 때, 서비스 전환·모델 조회·교정 시작·종료 시 자동 저장한다. Windows에서는 자격 증명 관리자에 서비스별로 분리하여 저장하고, 일반 설정에는 키를 넣지 않는다. macOS에서는 Keychain, Linux에서는 Secret Service를 사용한다. 저장소 이용에 실패하면 오류를 표시하고 현재 실행에서만 키를 사용하며, 평문 파일로 대체하지 않는다.

저장된 키가 있으면 우선 사용하고, 없으면 `.env`의 `OPENAI_API_KEY`, `OPENROUTER_API_KEY`를 초기값으로 사용한다. 키 입력란을 비우고 다른 컨트롤을 선택하면 해당 서비스의 저장된 키가 삭제된다. `.env`에 키가 남아 있으면 다음 실행 때 다시 초기값으로 사용된다. 키를 변경한 직후에는 모델 목록을 다시 조회해야 한다. 자막 내용은 선택한 서비스로 전송되며 사용 요금은 해당 서비스의 정책을 따른다.

일반 설정은 Qt 설정 저장소를 사용하며 Windows 위치는 `HKEY_CURRENT_USER\Software\drasys\srt-spellchecker`다. 작업 파일 목록과 실행 로그는 복원하지 않으며, 키 표시 상태는 매번 가림으로 시작한다.

폴더 추가 시 `.srt` 확장자는 대소문자를 구분하지 않으며, 기존 `_revised.srt`도 포함한 모든 SRT를 탐색한다. 심볼릭 링크 폴더는 순환 방지를 위해 재귀 탐색하지 않는다. 목록에서 제외할 파일을 선택해 제거할 수 있다. 실행 중 생성된 결과는 현재 작업 목록에 자동 추가하지 않는다.

결과는 원본 옆의 `<원본파일명>_revised.srt`에 저장한다. GUI는 원본과 기존 결과를 덮어쓰지 않으며 이름이 겹치면 `_revised_2.srt`, `_revised_3.srt`처럼 번호를 붙인다. 파일 목록에서 원본이나 결과를 더블클릭하면 해당 폴더를 연다.

**중단**은 진행 중인 API 요청이 끝난 뒤, 다음 재시도·배치·파일에 들어가기 전에 적용된다. 요청 제한 시간은 교정 180초, 모델 조회 30초다. 완료된 파일은 남기며 중단된 파일은 저장하지 않는다. 작업 중 창을 닫으면 중단 확인 후 작업 종료까지 기다린다.

개별 파일 읽기·저장 오류는 로그를 남기고 다음 파일로 진행한다. 인증·권한·잘못된 요청·없는 모델 오류는 작업 큐를 중단한다. 배치 교정 실패 등으로 일부 원문을 유지한 결과는 **검토 필요**로 표시한다.

## CLI 설정

1. `.env.example`을 복사해 `.env`를 만든다.
2. `.env`에 OpenAI 정보를 입력한다.

| 환경 변수 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `OPENAI_API_KEY` | O | - | OpenAI API 키 |
| `OPENAI_MODEL` | X | `gpt-5.6-luna` | 사용할 모델 |
| `OPENAI_REASONING_EFFORT` | X | `low` | 추론 강도 (`none`, `low`, `medium`, `high` 등 모델이 지원하는 값) |

## CLI 실행

프로젝트 디렉터리에서 editable 방식으로 설치한다. 설치 후 소스 코드 변경 사항이 바로 반영된다.

```powershell
uv tool install --editable .
```

파일 인자를 지정하면 기존 OpenAI 단일 파일 CLI로 실행한다. OpenRouter 및 폴더 일괄 처리는 GUI에서 제공한다.

```powershell
srt-spellchecker <srt파일>
```

설치 없이 프로젝트 디렉터리에서 직접 실행할 수도 있다.

```powershell
uv run srt_spellchecker.py <srt파일>
```

| 옵션 | 설명 |
|---|---|
| `--wrap` | 긴 줄을 최대 2줄로 나눔. 모델이 규칙을 어기면 코드에서 공백 기준으로 다시 나눔 |
| `--max-line-length N` | `--wrap` 사용 시 한 줄 최대 글자 수 (기본 23) |
| `--model NAME` | 모델 지정 (`OPENAI_MODEL`보다 우선) |

CLI 실행 결과는 `<원본파일명>_revised.srt` 파일로 생성되며, 기존 CLI와 같이 같은 이름이 있으면 덮어쓴다.

## 검토 로그

| 태그 | 의미 |
|---|---|
| `[되돌림]` | 줄 수 불일치 또는 문장부호 추가로 원본 유지 |
| `[재분할]` | `--wrap` 규칙 위반으로 코드에서 줄을 다시 나눔 |
| `[확인필요]` | `--wrap` 규칙을 맞출 수 없어 수동 확인 필요 |
| `[누락]` | 모델 응답에 해당 자막이 없어 원본 유지 |
| `[실패]` | 배치가 재시도 후에도 실패해 원본 유지 |

## 모델 관련 참고

### GUI

- OpenAI와 OpenRouter의 모델 목록 API를 호출하며 모델 ID와 OpenRouter 메타데이터를 보존함
- OpenRouter는 `reasoning.mandatory: false`이면 `reasoning.enabled: false`로 추론을 비활성화함
- 필수 추론 모델은 `supported_efforts` 중 `minimal`, `low`, `medium`, `high`, `xhigh`, `max` 순서로 지원하는 최저 강도를 선택함
- `supported_efforts: null`은 모든 강도 허용으로 해석하되 필수 추론 모델에 `none`을 보내지 않음
- 메타데이터 또는 강도 선택 정보가 없으면 지원 값을 추측하지 않고 모델 기본값을 사용함
- `exclude: true`는 추론 내용의 응답 제외이며, 자체적으로 추론 비용을 줄이는 옵션은 아님
- OpenAI 모델 목록에는 추론 지원 강도가 없으므로 GUI에서는 추론 파라미터를 강제하지 않음
- Chat Completions API를 사용함. OpenRouter는 `structured_outputs` 지원 시 JSON 스키마, `response_format`만 지원하면 JSON 모드, 둘 다 없으면 프롬프트로 JSON을 요청함. 응답은 항상 Pydantic으로 검증함
- OpenAI는 JSON 스키마 구조화 출력을 사용함. 목록에 표시되더라도 선택한 모델이 텍스트 교정·Chat Completions·구조화 출력을 지원하지 않으면 API 오류가 표시될 수 있음

OpenRouter 추론 정책 기준: [Reasoning Tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

### 기존 CLI

- `temperature`, `top_p`, `max_tokens` 등 미지원 파라미터를 전달하지 않음
- Responses API와 `reasoning.effort`로 추론 강도를 제어함
- 구조화 출력(JSON 스키마, strict)으로 응답 형식을 강제함
- 인증 오류, 잘못된 요청, 없는 모델 등 재시도해도 의미 없는 오류는 즉시 중단함

## 테스트

```powershell
uv run pytest
```

네트워크를 호출하지 않는 서비스 요청·응답 테스트, SRT 처리 회귀 테스트, Qt 이벤트 및 백그라운드 작업 테스트를 포함한다. 실제 API 교정에는 유효한 키와 해당 모델 이용 권한이 필요하다.
